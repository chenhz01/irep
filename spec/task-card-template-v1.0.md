## 任务卡（必填字段，缺一即立案不完整）

```markdown
## 任务卡：<任务名>

**目标数 = N + 量级依据**            ← 无此字段视同立项不完整
**参考系统 X = <名称 + 许可证>**     ← 无参考系统写「无」；有就必须过闸
**irep_gate 判决 = <BLOCKED/REPLICA/DERIVATIVE/BREAKTHROUGH/CONDITIONAL-*>**  ← 开工硬闸
**开工授权 = <委托方明示 / 无参考系统免闸>**
```

## 开工硬闸（H-GATE，顺序执行）

1. **有参考系统 → 先跑 `gate/irep_gate.py`（本仓），判决未出不得开工。** 判决留痕自建台账（jsonl）。
2. 判决 `BLOCKED` → 任务终止，改方向或升级人工；**禁「先做着看」**。
3. 判决 `REPLICA` → 禁称第二代/突破；可继续，但对外文本必须带来源声明。
4. 判决 `DERIVATIVE` → 合法可交付；对外前补署名（L2）。
5. 判决 `BREAKTHROUGH` / `CONDITIONAL-*` → 记录差异度 r 与四前提；后者每前提一条闭合证据。
6. **无参考系统（纯原创/自有资产）→ 免闸**，卡上写「无参考系统」即放行。

## 收口必填（并入三态制第四要素）

- [ ] 突破件对账通过（未过不得标完毕）
- [ ] 实跑证据：命令 + 关键输出（R-U3）
- [ ] TM=<指标>: 改前→改后（证据）｜ BC=赚钱/省钱/暂无+触发条件（F12）
- [ ] 审计器挂载点声明（触发器三选一落真）
- [ ] 若产出将对外：过发表五问 + 敏感字段剥离 + GitHub push 人工确认（二级授权）
