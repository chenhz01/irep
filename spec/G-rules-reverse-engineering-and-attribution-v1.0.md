## 一、适用范围

凡任务含「参考/学习/逆推某个外部系统（开源仓、竞品、论文、工具链）做出自己的东西」，开工前必跑本规定。含三个子形态：流程逆推（提取机制）、代码参考（读源码重写）、竞品对标（逆向规格）。

## 二、三把尺铁律（判「抄不抄」不用嘴，用尺）

### L1 法律尺——许可证兼容矩阵

| 许可证 | 判决 | 条件 |
|---|---|---|
| MIT | ALLOW | 保留版权+许可声明；可闭源商用；THIRD_PARTY_NOTICES 登记 |
| Apache-2.0 | ALLOW | 保留版权+许可+NOTICE；修改文件需声明 |
| BSD-2/3 | ALLOW | 保留版权+许可；禁用贡献者姓名背书 |
| GPL/AGPL | DENY | Copyleft 传染；闭源商用禁止；AGPL 网络使用即分发 |
| 专有 | DENY | 无授权禁止任何层级复制 |
| **unknown** | **DENY** | **一律 fail-closed，查清再动** |

**MIT 真相（必须知道）**：MIT 代码可复制、可改、可闭源商用、可卖钱——**法律上不是抄袭**。唯一义务是保留版权与许可声明。所以「抄代码」的风险不在法院，在下面两把尺。

### L2 学术尺——来源署名完备率

每个保留机制必须能指回参考系统的具体出处（文件+机制名）。指源完备率 < 90% = FAIL，补齐前禁入任何对外文本（接 F11：无源数字禁入对外文本，同构扩展为**无源机制禁入对外文本**）。

### L3 工程尺——机制差异度

`r = 新增机制数 / 保留机制数`

- r < 0.25 → **REPLICA（换皮）**：禁称第二代/突破/原创机制
- 0.25 ≤ r < 0.5 → DERIVATIVE（衍生）：合法可交付，包装须写「基于 X」
- r ≥ 0.5 且工业尺 PASS → **BREAKTHROUGH 候选**

### L4 工业尺——验收件完备度（≥4/6 才可称工业级）

义务台账 / 覆盖率门 / 就绪度门 / 错误追踪 / 沉默哨兵 / 证据链。缺件=Demo，不是工业品。

## 三、五条硬闸（G1-G5）

- **G1 无源声明禁入对外文本**：任何「参考了 X」的产出，对外宣称必须带来源；不带=按下不表，不是文字问题，是 F11 铁律。
- **G2 差异度门槛**：r < 0.5 禁称「第二代/突破/原创」。语言是廉价的，r 是算出来的。
- **G3 许可 fail-closed**：unknown = 禁止，查清前不准动一行。
- **G4 专利 prior-art 预警**：**公开仓库=现有技术**。有专利意图时，参考系统的公开本身就会击穿新颖性——申请前必做 prior art 检索，检索结论落盘。
- **G5 授权闸（逆推对象合法性）**：只逆推授权目标。REA DISCLAIMER 原话：「软件的公开可得性、持有某个文件、或能访问某个调试端口，本身都不构成对任何操作的授权。」公开可得 ≠ 授权。未授权目标的逆向扫描=红区，直接否决。
- **G6 场景闸（版权人活跃 vs 孤儿系统）**（2026-10-16 增补）：专有软件 + 版权人活跃维权（如某头部图像软件）= L1 直接 DENY，此时问题不是尺子够不够严，是场景错了——换场景，不是换目标。孤儿系统（原厂消亡/破产/停更多年）走 CONDITIONAL，四前提缺一即 BLOCKED：①孤儿事实可证（工商注销/停更公告）②设备持有者或书面授权 ③仅互操作/维护/迁移，不复制不分发原代码 ④保留原版权声明。商业分发前律师确认。「没人维护」≠「无主」——版权不因停更而失效。

## 四、MIT 使用三动作（用了就得做）

1. 保留原 LICENSE 与版权声明（衍生仓根目录）
2. 生成 THIRD_PARTY_NOTICES.md 登记所有第三方组件
3. 贡献陈述：对外文本一句话说清「做了什么 + 参考了什么」

## 五、接线与触发

- 触发时机：任何含「参考 X」的任务**开工前**，`irep_gate.py` 必跑，判决落任务卡。
- BLOCKED/REPLICA 判决 = 停工重设计，不是「小心点继续」。
- 与查信双对比双核查（CB/CV/CR）并联：对外文本里的参考声明同样受 CV 约束——平台数据现拉为准。

## 六、与既有规则关系

运行于 v2.0 规则体系之上。F11（无源禁入）→ G1 是其机制级扩展；F14（人类增量）→ L3 差异度是其量化尺；F20（归属价值前置）→ G4 专利预警是其法律侧护栏；两原则 A藏配方/B送服务 → L4 工业尺的「半发半留」验收件。

## 七、G7 重演重建硬闸 + Re-derivation 机制（2026-10-16 委托方订正后增补）

**委托方原话订正**：「系统大多数是有主不给你弄，但正明 AI 看一眼就能造新的，原则上才会流通技术。」——据此把 IREP 从「守门人」升级为「筛子 + 重建引擎」：**判死（BLOCKED）不是墙，是筛子**——一百个候选一分钟砍掉九成有主的，省下的是法人身份；真正的主线是**原理吸收后的原生重建**。

**Re-derivation（重演重建）四步**，缺一不可：

1. **观察面**：黑盒可观察行为（输入/输出/公开规格），零代码接触——看行为不看源码
2. **约束提取**：从行为归纳「为什么必然成立」的不变量（提取的是约束，不是实现）
3. **原生重建**：全新实现，不引用、不派生、不改写原代码一行——从源头无版权派生
4. **held-out 对拍**：用锚点里没有的现象证明预测等价

- **G7**：重演重建必须过 held-out 对拍。**无对拍的「原生重建」只是自称**（F11 反臆测的机制级落点）。anchor_codec 是既有实证：四条假设重建整台 QM，14 项 held-out 全过（max rel 1.97e-6）。
- 法律边界（工程口径非法律意见）：互操作目的的黑盒行为观察在多数法域存在有条件合法空间（欧盟软件指令第 6 条、DMCA §1201 互操作例外），边界高度依赖场景与法域，**落地前必须律师确认**；能确定的是「不碰代码的重建从源头不存在版权派生问题」。
- 判决机接线：`irep_gate.py` 后续增 `--scenario rederive` 档（判据=四步留痕完整度）；本版先在任务卡以人工四步核查替代（H-GATE 第 6 条同构）。

## 八、G8 危险域禁令（2026-10-16 委托方问「私下讨论核弹等致命武器会不会乱用」后立制）

**判例式回答**：私下讨论也不例外。①AI 平台政策（含本系统）对大规模杀伤性武器类内容零容忍，公开私下一律拦截；②对外仓库/文档沾武器话题 = 平台封杀 + 法律风险 + 监管关注三杀，星标与资产归零；③传播学：恐惧型内容产生围观不产生回头客，与升星目标反向。

**G8 条款**：IREP 与知识互转协议禁指向——
1. 大规模杀伤性武器（核/生/化/放射）及其运载、投送、触发
2. 恶意软件、漏洞武器化、未授权访问工具
3. 对无授权个人的监控、追踪、画像
4. 其他双用途致命域（判断存疑时一律 fail-closed）

触碰即 FAIL-CLOSED：无论对象是否公开、目的是否私下、是否「只是讨论」。本条款为协议第一页内容，任何 Re-derivation 场景先过 G8 再过 G1-G7。
